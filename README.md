# פיתוח חברותא מרכז – שאלות לוועדה (גרסת ניסיון)

אתר אנונימי לשליחת שאלות לוועדת פיתוח חברותא, עם מאגר שו"ת וממשק למשרתים.

**הקבצים בתיקייה**

| קובץ | מה הוא |
|---|---|
| `index.html` | האתר כולו, כולל ממשק המשרתים |
| `admin.html` | קיצור דרך לממשק המשרתים |
| `config.js` | כתובת מסד הנתונים והמפתח הציבורי. **צריך למלא** |
| `na-logo.jpg` | הלוגו |
| `supabase-setup.sql` | הקמת מסד הנתונים. מריצים פעם אחת ב-Supabase, ולא חייבים להעלות אותו לגיטהב |

---

## מדריך העלאה (בערך 20 דקות)

### שלב 1: מסד הנתונים (Supabase)

1. נכנסים ל-**supabase.com**, לוחצים **Start your project**, ונכנסים עם **Continue with GitHub**.
2. לוחצים **New project** וממלאים:
   - **Name:** `fd-merkaz` (שם פנימי, לא מופיע בשום לינק ציבורי)
   - **Database Password:** לוחצים *Generate a password* ושומרים אותה במקום בטוח
   - **Region:** `Central EU (Frankfurt)`, הכי קרוב לישראל
   - לוחצים **Create new project** ומחכים כ-2 דקות.
3. בתפריט שבצד בוחרים **SQL Editor**, ואז **New query**.
4. פותחים את הקובץ `supabase-setup.sql`, מעתיקים את **כל** התוכן, מדביקים ולוחצים **Run**. אמור להופיע *Success*.
5. **בוחרים סיסמה למשרתים.** פותחים שוב **New query**, מדביקים את השורה הבאה עם סיסמה משלכם (לפחות 10 תווים), ולוחצים **Run**:
   ```sql
   select fd_set_admin_password('כאן-סיסמה-ארוכה-משלכם');
   ```
   ⚠️ את הסיסמה הזו מוסרים רק למשרתי הוועדה. לא כותבים אותה באף קובץ, ולא מעלים אותה לגיטהב.
6. בוחרים **Project Settings** (גלגל השיניים) ואז **API Keys**, ומעתיקים שני דברים:
   - **Project URL**, שנראה כמו `https://abcdefgh.supabase.co`. אם הוא לא מופיע שם, מחפשים אותו ב-*Data API*.
   - **Publishable key**, שמתחיל ב-`sb_publishable_`. אם יש רק *Legacy API keys*, לוקחים את ה-**anon public**.
   - ❌ **לא** את ה-*secret* ולא את ה-*service_role*. המפתחות האלה פותחים גישה מלאה למסד הנתונים.
7. פותחים את `config.js` בעורך טקסט (למשל TextEdit), מדביקים את שני הערכים במקום הטקסט "הדביקו-כאן…", ושומרים.

### שלב 2: האתר בגיטהב, עם לינק בלי השם האישי

כתובת אתר בגיטהב נבנית משם החשבון שמחזיק אותו. לכן פותחים **ארגון** בשם ניטרלי, והלינק יהיה על שמו.

1. ב-**github.com** לוחצים על **+** (למעלה), ואז **New organization** ו-**Create a free organization**.
   - **Organization name:** למשל `na-fd-merkaz`. אם השם תפוס, בוחרים שם ניטרלי אחר. **זה השם שיופיע בלינק.**
   - **Contact email:** עדיף מייל שירות של הוועדה.
2. בתוך הארגון לוחצים **New repository**:
   - **Repository name:** בדיוק `na-fd-merkaz.github.io`, כלומר שם הארגון ואחריו `.github.io`
   - **Public**, ואז **Create repository**.
3. בעמוד המאגר לוחצים על הקישור **uploading an existing file**, גוררים פנימה את הקבצים `index.html`, `admin.html`, `config.js` (אחרי שמילאתם אותו), `na-logo.jpg` ו-`README.md`, ולוחצים **Commit changes**.
4. נכנסים ל-**Settings** ואז **Pages**, ובוחרים:
   - **Source:** *Deploy from a branch*
   - **Branch:** `main`, תיקייה `/ (root)`, ואז **Save**.
5. אחרי 1–2 דקות האתר יעלה בכתובת: **`https://na-fd-merkaz.github.io`**

> 💡 **לגבי פרטיות:** הלינק עצמו לא יכלול את השם שלך. אבל המאגר בגיטהב ציבורי, ומי שייכנס להיסטוריית השינויים שלו יוכל לראות מאיזה חשבון הקבצים הועלו. כדי שגם זה לא יופיע, אפשר להעלות מחשבון גיטהב ייעודי של הוועדה, או להשתמש ב-**Cloudflare Pages**: *Workers & Pages*, אחר כך *Create*, *Pages* ו-*Upload assets*. שם מעלים את התיקייה בלי מאגר ציבורי, ומקבלים לינק כמו `na-fd-merkaz.pages.dev`.

### שלב 3: בדיקה

1. נכנסים לאתר ושולחים שאלת ניסיון באפשרות **האנונימית**, ורושמים את הקוד.
2. בתחתית העמוד לוחצים **כניסת משרתים**, ונכנסים עם הסיסמה משלב 1.5.
3. פותחים את הפנייה, כותבים מענה ולוחצים **שלח מענה**.
4. בלשונית **בדיקת סטטוס פנייה** מזינים את הקוד. התשובה אמורה להופיע.

אם בתחתית העמוד כתוב **"אבטיפוס להדגמה בלבד"** במקום **"גרסת ניסיון"**, האתר לא מחובר למסד הנתונים. זה אומר שצריך לבדוק את `config.js`.

## חשוב לדעת

- **אבטחה:** לציבור אין גישה ישירה לטבלאות. הוא יכול רק לשלוח פנייה, לבדוק סטטוס עם קוד ולקרוא את המאגר. פניות ופרטי קשר נגישים רק אחרי כניסה עם סיסמת המשרתים, שנשמרת מוצפנת בשרת. ניסיונות לנחש קודים או סיסמה נחסמים אוטומטית.
- **מחיקה אוטומטית:** טלפונים ומיילים נמחקים 30 יום אחרי שפנייה נסגרה, והפניות עצמן נמחקות 180 יום אחרי הסגירה.
- **החלפת סיסמה ברוטציה:** מריצים שוב ב-SQL Editor את `select fd_set_admin_password('סיסמה-חדשה');`. כל מי שהיה מחובר מנותק מיד.
- **השהיה בחינם:** ב-Supabase החינמי, פרויקט שלא נכנסו אליו 7 ימים נכנס למצב שינה. מחזירים אותו בלחיצה על *Restore* בלוח הבקרה, או פשוט משתמשים באתר באופן קבוע.
- **גרסת ניסיון:** לפני פרסום רחב מומלץ לעבור על האפיון (`אפיון-פלטפורמת-שות-פיתוח-חברותא`), ובמיוחד על אישור של שני משרתים לכל תשובה ועל אורך הקוד הסודי.
